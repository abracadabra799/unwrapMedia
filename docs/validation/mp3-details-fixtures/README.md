# MP3 / ID3 fixture provenance

Generated by `generate.py` using ffmpeg/libmp3lame synthetic440Hz sine waves and a Pillow-generated8x8 PNG cover (no personal data). Regenerate from repository root:

```
python3 docs/validation/mp3-details-fixtures/generate.py
python3 docs/validation/mp3-details-fixtures/dump.py app/src/test/resources/mp3-details/mpeg1-v23.mp3 app/src/test/resources/mp3-details/mpeg2-v24.mp3 app/src/test/resources/mp3-details/mpeg25-v24.mp3
```

`verified-bytes.txt` is an independent pre-implementation inventory. MPEG1 uses48kHz/128kbps and ID3v2.3 with UTF16 title and APIC cover; MPEG2 uses24kHz/64kbps, MPEG2.5 uses12kHz/32kbps; both use ID3v2.4 UTF8 titles. Encoder version strings and byte counts can change across tools; unit tests pin checked-in fixture values. Native comment metadata is emitted by ffmpeg as TXXX(comment), not COMM; COMM and other unsupported writer features are explicitly synthetic unit-test frames.

Definitions cross-checked with official ID3v2.4 structure/frames at https://id3.org/id3v2.4.0-structure and https://id3.org/id3v2.4.0-frames. Synthetic unit-test cases cover extended headers/footer, COMM UTF16 alignment, URL/PRIV/UFID/counters, frame grouping/DLI/unsync, unknown/unsupported metadata, malformed lengths and expansion limits. They are not attributed to ffmpeg. Source offsets for de-unsynchronised fields refer to the original physical span including inserted bytes.

Footer integration tests author a standard v2.4 footer over the existing real MPEG2/AAC streams; they do not claim ffmpeg emitted a footer. MPEG/ADTS frame bytes stay unchanged, while tag flags/footer are authored explicitly. v2.3 tag-wide unsynchronisation and v2.2 frames remain explicitly uninterpreted; v2.4 per-frame unsync is decoded with physical source mapping. Compression/encryption is identified and left opaque, not decoded as plain text.
